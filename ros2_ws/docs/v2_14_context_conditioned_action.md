# v2_14 Context-Conditioned Action

A phase classifier + per-phase target-joint regressor trained on the
v2_13 encoder's 32-dim latent. Reads the v2_13_v2 multi-phase
context_log.parquet, encodes each 74-dim context vector with the
frozen v2_13_v2 encoder, and trains a small MLP head with two
output heads:

  - classifier: 32 -> 32 -> 9 (CrossEntropy over 9 phase classes:
    UNKNOWN, IDLE, MOVE_TO_START, APPROACH, CHECK_ALIGNMENT, SEARCH,
    HOVER_ABOVE_HOLE, INSERT, INSERTED, RETREAT, DONE, ABORT,
    COMPLETE — the canonical task phase enum)
  - regressor: 32 -> 32 -> 6 (MSE against the per-phase mean target
    joint position)

The "context-conditioned action" interpretation: the classifier
output is the discrete action (which controller law to activate in
this phase), and the regressor output is the per-phase target joint
pose the policy should be commanding. The two heads share the
32-dim latent and the same Adam optimizer.

This is offline training only; it does not need ROS. The script is
registered as a console script
(`ros2 run perception_pipeline v2_14_context_conditioned_action -- ...`)
for symmetry with v2_13.

## Why a classifier+regressor, not a single action network

The 1mm/2mm cartesian precision ceiling with the working JTC means
real SEARCH/INSERT/ABORT trials are not reachable. The multi-phase
dataset is generated by `synthetic_phase_publisher` on a frozen arm,
so the per-phase joint positions are all the initial pose. A
direct "context -> joint command" regressor would trivially learn
to output the initial pose. A phase classifier is the meaningful
non-trivial task on this dataset: it validates that the v2_13
encoder latent is phase-discriminative. A per-phase mean target
joint regression is added as a sanity check.

## Inputs

- `--input-parquet` path to `context_log.parquet` (multi-phase).
- `--encoder-pt` path to v2_13 encoder checkpoint.
- `--scaler-json` path to v2_13 scaler.json (per-feature min/range).

## Outputs (in `--output-dir`)

| File | Purpose |
|---|---|
| `action_classifier.pt` | the PhaseHead (classifier+regressor) state dict, dict with `state_dict`, `input_dim`, `num_classes`, `joint_dim`, `hidden`, `dropout`. v2_15 loads this for the with-encoder arm |
| `action_metadata.json` | final test accuracy, test CE, test MSE, per-class precision/recall, confusion matrix, full loss curve, dataset, timestamp |
| `confusion_matrix.png` | 9x9 confusion matrix (if matplotlib is available) |
| `per_phase_target_pose.json` | per-phase mean target joint pose (the regression targets) |
| `data_validation_report.json` | input shape, NaN/Inf, per-class counts |

## Preprocessing (committed in the trainer)

1. **Drop empty-camera rows** (rgb_sum<1, depth_w=0, depth_h=0).
2. **Apply v2_13 transforms** (log1p on depth values 50-53, min-max
   scaling using v2_13 scaler.json). Identical to v2_13 inference.
3. **Frozen v2_13 encode** 74 -> 32, no gradient flow.
4. **80/20 deterministic split** (seed=0) on the encoded latent.
5. **Joint CE + MSE** training of the PhaseHead.

## Model

- Input: 32 (v2_13 encoder latent)
- Hidden: 32 (ReLU + Dropout 0.10)
- Classifier head: 32 -> 9
- Regressor head: 32 -> 6
- ~1.4K parameters (just the head; encoder is frozen)
- Optimizer: Adam, lr 1e-3, weight_decay 1e-4
- Batch size 64, 200 epochs (default; tunable)
- Loss: CrossEntropyLoss (phase) + MSELoss (joint)

## Reproducing the v2_14_v1 baseline

```
source /opt/ros/jazzy/setup.bash
source /tmp/pos_controllers_setup.bash
source install/setup.bash
ros2 run perception_pipeline v2_14_context_conditioned_action -- \
    --input-parquet diagnostics/perception_pipeline_synthetic_multiphase_v1/context_log.parquet \
    --encoder-pt diagnostics/perception_pipeline_v2_13_encoder_v2/encoder.pt \
    --scaler-json diagnostics/perception_pipeline_v2_13_encoder_v2/scaler.json \
    --output-dir diagnostics/perception_pipeline_v2_14_action \
    --epochs 200 --batch-size 64 --lr 0.001 --seed 0
```

Expected outputs:
- `final_test_acc = 1.000` (100% on the test split)
- `final_test_ce  = 0.0147`
- `final_test_mse = 0.000000` (target = per-phase mean = initial pose)
- smoke test prints `logits shape (8, 9) reg shape (8, 6)`
- `confusion_matrix.png` shows a clean diagonal

The 100% test accuracy is partly because the multi-phase dataset
is synthetic and the only thing that varies per phase is the
`phase_int` (index 72) and the `safety_int` (index 73) in the
74-dim context vector. The classifier is essentially reading off
the phase label from the input. This validates the pipeline but
is not a strong claim about phase-discriminative representation
learning on a real-world dataset.

## Limitations

- The synthetic multi-phase dataset has a frozen arm. Per-phase
  joint positions are all the initial pose, so the regressor
  learns to output the initial pose regardless of context. This
  is by design (the real multi-phase data is unreachable with
  the working JTC) but it means v2_14's regressor head is not
  yet a "context-conditioned action" in the control-theoretic
  sense; it is a placeholder for the integration point.
- The classifier is reading the `phase_int` from the context
  vector. A real dataset would have the phase implied by the
  sensor data (RGB, depth, wrench, joint), not declared by the
  publisher, and the classification would be a meaningful task.
- v2_14 does NOT publish /joint_trajectory corrections to the
  JTC. Wiring v2_14 into a live ROS node is a downstream task.
